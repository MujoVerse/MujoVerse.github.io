本页列出 MujoVerse 对外声明的能力，以及支撑它的测试和实测数值。原始日志、截图和大文件放在 Hugging Face 数据集 [MujoVerse/mujobots-evidence](https://huggingface.co/datasets/MujoVerse/mujobots-evidence)，各仓库的 `docs/evidence/` 目录里有对应的小文件和说明。

除非特别注明，数值来自 macOS arm64 上的真实 Minecraft 服务器（GameTest）或真实客户端，不是单独的 MuJoCo 脚本。

## 控制器与参考实现一致

| 声明 | 证据 |
|---|---|
| T2 WALK 网络在 JVM 里的输出与原始 TorchScript 一致 | `PolicyParityTest`：逐元素误差 ≤ 3×10⁻⁵ |
| T2 WALK 控制器（观测历史、启动过程、目标角）与团队 Arena 运行时一致 | 同一测试：80 个完整控制帧，目标角逐元素误差 ≤ 3×10⁻⁵ |
| 50 Hz 策略、500 Hz 力矩 PD | 真实服务器：4,500 个物理子步中恰好 450 次推理 |
| 跨存档的确定性状态 | 原生和控制器状态序列化往返完全一致；退出重进后同一 UUID 继续行走 |

## 运动与恢复

| 声明 | 证据 |
|---|---|
| T2 在 MC 地形上行走 | GameTest 前进 2.44 m；真实客户端前进 2.90 m，重进存档后再前进 3.46 m，竖直余弦始终 > 0.998 |
| T2 摔倒后自主起身 | 原版仰卧、俯卧起身网络（164 维观测、31 维动作）；`RecoveryParityTest` 与原始 Python 运行时数值一致；`RecoveryNativeTest` 从仰卧、俯卧两种初始状态出发，只靠原生接触和电机力矩起身（初始化后不允许直接写根位姿），交接后继续行走 |
| Python 闭环驾驶 | 无界面服务器上 T2、G1 各走 1.5 m 正方形：4/4 航点，回到起点误差约 0.21 m |

## 数据接口

| 声明 | 证据 |
|---|---|
| 录制文件忠实于原生状态 | `check-recording.py` 用独立 MuJoCo 模型逐帧做正运动学：T2 10 s（500 帧）、G1 30 s（1500 帧），所有刚体最大位置误差 0 m |
| 刚体位姿流完整、低延迟 | 每台 5,001 帧、500 Hz：零丢帧、零序号缺口；采样到 Python 延迟中位数约 0.2 ms，P99 约 0.5 ms；带宽约 3.4 MB/s（T2） |
| 桥接在真实专用服务器上可用 | Fabric 1.21.1 专用服务器，无玩家在线：控制台 `/minepilot bridge start`，`bridge.json` 权限 0600，Python 客户端驱动 T2 前进约 1.5 m，竖直度 0.997，正常关服 |
| 桥接只对本机开放 | GameTest 覆盖鉴权、OP 权限、端口回退、浏览器 Origin 拒绝、指令超时、玩家接管、断线释放 |

## 性能

`MujoBots/scripts/benchmark-physics.sh` 在 macOS arm64（Apple 芯片）上测量每个服务器 tick 里物理和控制所用的时间（每 tick 25 个 2 ms 原生步，含 T2 WALK 控制计算；不含 Minecraft 自身、地形采集和场景重建）。Minecraft 每 tick 的总预算是 50 ms。

| 实时 T2 | 刚体结构 | 平均 ms / tick | P95 |
|---:|---:|---:|---:|
| 1 | 0 | 3.3 | 3.7 |
| 5 | 0 | 17.4 | 19.6 |
| 10 | 0 | 34.2 | 37.9 |
| 0 | 10 | 0.9 | 0.9 |
| 0 | 100 | 8.8 | 8.9 |

耗时随机器人数量线性增长，大约 10 台实时 T2 会用掉三分之二的 tick 预算。

## 发布内容的许可检查

每个发布的 jar 在构建时都会自动检查：每个文件都有对应的许可声明和来源记录，受限文件按哈希清单拦截，推理库带有三个平台的原生库。
